# Komga-CN 1.28 Modern UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the verified Komga-CN 1.26.0 baseline, preserve every capability, modernize its complete Vue/Vuetify UI, and publish a verified `shenshangshang/komga-cn:1.28.0` image.

**Architecture:** Keep the 1.26 router, services, stores, readers, Kotlin backend, MySQL support, and page-prefetch flow intact. Modernize through semantic tokens and existing shared components, then prove parity with inventories, full builds, browser checks, container smoke tests, and Docker Hub pull-back verification.

**Tech Stack:** Kotlin/JVM 21, Spring Boot, Gradle, Vue, Vuetify, JavaScript/TypeScript, CSS, Docker, MySQL 8.4.

## Global Constraints

- Base implementation on `d4bb9e4c`; its JAR reports `Implementation-Version: 1.26.0`.
- Archive current 1.27 commits and every dirty file before restoration.
- Do not change backend contracts, authorization, database or prefetch behavior, reader data flow, service/store contracts, or route meaning for visual reasons.
- Follow `design-system/komga-cn-1-28/MASTER.md`: variance 5/10, motion 2/10, density 8/10.
- No runtime font, icon, analytics, or styling CDN dependencies.
- Publish `1.28.0` first; update `latest` only after the pulled image passes verification; keep `1.26.0` unchanged.
- Never persist GitHub or Docker Hub credentials in Git URLs, files, image layers, build arguments, or history.

---

## Planned file boundaries

- `docs/superpowers/audits/1.26-baseline.md`: baseline evidence and findings.
- `docs/superpowers/audits/1.28-final.md`: parity, review, accessibility, build, and image evidence.
- `scripts/verify-route-parity.sh`: baseline/current route comparison.
- `scripts/smoke-komga.sh`: health, static UI, and authentication-boundary smoke checks.
- `komga-webui/src/styles/design-tokens.css`: semantic light/dark design tokens.
- Existing `components/**` and `views/**`: presentation changes only; public props/events and business logic remain compatible.
- `gradle.properties` and `Dockerfile`: release version update after all quality gates pass.

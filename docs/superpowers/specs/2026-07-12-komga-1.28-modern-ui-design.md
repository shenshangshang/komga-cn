# Komga-CN 1.28 Modern UI Design

## Objective

Restore the known-good 1.26.0 codebase and modernize its complete frontend without changing backend contracts, authentication semantics, database behavior, prefetch behavior, reader data flow, or route meaning. The resulting image will be published as `shenshangshang/komga-cn:1.28.0` and, after verification, as `latest`.

## Baseline and preservation

- Preserve the current 1.27.x work, including its uncommitted changes, under a dated backup branch before restoration.
- Base the implementation on commit `d4bb9e4c`, which builds the verified `Implementation-Version: 1.26.0` image.
- Preserve the MySQL 8.4 and page-prefetch backend changes already present in the 1.26 baseline.
- Remove credentials from Git remote URLs and never store Docker Hub or GitHub credentials in the repository, image layers, shell history, or build arguments.

## Functional invariants

All existing 1.26 routes and capabilities remain reachable and functional, including:

- login, startup, welcome, account, self-authentication activity, and API keys;
- home, dashboard, global search, history, announcements, and updates;
- libraries, series, books, one-shots, collections, and read lists;
- book import, read-list import, missing posters, media analysis, duplicate files, and duplicate pages;
- server settings, server management, users, metrics, reading statistics, and UI/user settings;
- Divina and EPUB readers, progression updates, page retrieval, page prefetching, and reader preferences;
- localization, light/dark/system themes, responsive navigation, keyboard access, and error/empty/loading states.

No backend endpoint, DTO, authorization rule, persistence model, environment variable, or server-side behavior will be changed solely to accommodate the new appearance.

## Design direction

The product is a personal digital comics and books library for readers and administrators. Its primary job is to make large libraries feel browsable and reading progress immediately understandable.

### Visual identity

The installed UI UX Pro Max skill was queried for a media-library management dashboard, comic/ebook reader, content-first layout, Vue stack, dense information display, light/dark modes, and accessibility. Its most appropriate recommendation was **Swiss Modernism 2.0**: a rational modular grid, disciplined hierarchy, excellent performance, and WCAG-friendly contrast. Newsletter structures, tactile/deformable controls, decorative stagger animations, and child-oriented fonts returned by broader matches were rejected because they conflict with Komga's application architecture, administrative workflows, and motion-sensitivity requirements.

- **Library Ink** `#17202A`: primary text and dark surfaces.
- **Reading Paper** `#F5F7FA`: light application background.
- **Shelf Blue** `#356AE6`: primary action and active navigation.
- **Bookmark Coral** `#EF6A5B`: reading progress and attention accent.
- **Archive Teal** `#168C88`: success and completed states.
- **Quiet Slate** `#697586`: secondary labels and metadata.

Dark mode uses the same semantic roles with contrast-adjusted surfaces rather than a separate visual identity. Colors are exposed as Vuetify/theme tokens and CSS custom properties; feature components do not hardcode palette values.

Typography favors system-native Chinese and Latin rendering for privacy, performance, and offline operation. Display hierarchy uses a restrained rounded sans treatment; body and metadata remain highly legible at dense library scale.

The font stack prioritizes `Noto Sans SC`, `Noto Sans TC`, and system UI fallbacks when present, without downloading fonts at runtime. This follows the skill's multilingual recommendation while preserving offline usability and avoiding render-blocking font requests.

### Layout

- Desktop: persistent, collapsible library rail; contextual top bar; fluid content canvas.
- Tablet: compact rail with preserved labels where space permits.
- Mobile: top app bar plus bottom primary navigation; secondary/admin destinations in a sheet.
- Content density is user-respecting: responsive cover grids, stable card aspect ratios, and list alternatives where the existing setting provides them.

### Signature interaction

The distinctive element is a "living shelf" card system: cover art remains dominant while progress, unread count, status, and primary action occupy a consistent lower information rail. Hover and focus reveal secondary controls without moving layout. Reduced-motion mode removes transitions while preserving state changes.

Motion is intentionally set to 2/10: 150-200 ms state transitions using opacity or color, no decorative page choreography, no long list staggering, and no layout-changing scale effects. Information density is 8/10 for administration and browse screens, with touch targets never reduced below 44 CSS pixels.

## Component strategy

Modernization proceeds through shared layers so all pages remain behaviorally consistent:

1. semantic theme tokens and global typography/spacing;
2. application shell, navigation, toolbar, and responsive breakpoints;
3. reusable media cards, data rows, filter/search controls, dialogs, empty/loading/error states;
4. reader chrome, preserving the reader engines and event/data contracts;
5. page-by-page visual adoption without replacing route components or API services.

Existing Vue/Vuetify architecture remains in place. A framework migration is explicitly out of scope because the failed 1.27 rewrite demonstrated that replacing the application surface risks dropping business functionality.

## Data flow and error handling

Views continue to call the existing stores/services and consume the existing API types. UI changes may reorganize presentation state but must not duplicate server state or introduce alternate endpoint clients.

Loading, empty, unauthorized, forbidden, network-failure, and server-failure states use shared components with actionable text. Destructive actions retain confirmation. Toasts and action labels use consistent verbs. Secrets and server error internals are never rendered or logged by new components.

## Accessibility and responsiveness

- WCAG 2.2 AA color contrast for text and controls.
- Complete keyboard navigation and visible focus indicators.
- Semantic headings, form labels, dialog names, and live regions for asynchronous feedback.
- Touch targets of at least 44 CSS pixels for primary mobile actions.
- `prefers-reduced-motion` respected globally.
- Zoom and reflow tested at 200% and narrow mobile widths.

## Verification gates

### Baseline audit

- Compare the restored source tree with `d4bb9e4c` and document intentional differences.
- Run secret, dependency, static-analysis, backend test, and frontend build checks.
- Build and run the unchanged 1.26 baseline before frontend modifications.

### Functional parity

- Produce a route inventory from the 1.26 router and prove every route remains registered.
- Exercise authentication, browsing, administration, settings, and both reader families against a running container.
- Verify MySQL configuration and page-prefetch behavior remain wired through the existing backend.

### Final quality

- Frontend production build and applicable unit/component tests pass.
- Full Gradle test/build passes.
- Final code review has no unresolved P0/P1 findings; P2 issues affecting correctness, security, accessibility, or maintainability are fixed.
- Container starts healthy with persistent config/data volumes and shows version 1.28.0.
- Image is inspected for embedded credentials and unexpected root-only runtime requirements.

## Release

- Build `shenshangshang/komga-cn:1.28.0` reproducibly from the audited commit.
- Push `1.28.0` first; pull it back from Docker Hub and run the smoke suite against the pulled digest.
- Only after pull-back verification, push the same digest as `latest`.
- Do not overwrite or delete `1.26.0`; it remains the rollback image.

## Out of scope

- Backend API redesign, database migration, reader engine replacement, new business features, and deletion of historical Docker Hub tags.
- Reusing the incomplete 1.27 frontend as the implementation base. It remains an audit/reference artifact only.
